One pattern in every system

Retrieval keeps agents grounded in evidence. Agents make the judgements. A checker can always say no. Code enforces the rules.

  1. Retrieval groundsAnswers come from cited evidence, not model memory.
  2. Agents proposeEach agent has one job and makes one kind of call.
  3. A checker can say noA judge, verifier or human can veto any output.
  4. Code enforcesPermissions, approvals and logs live in code, not prompts.

How I work

Every AI build runs as a delivery loop: six stages, each with a product question and the thing I build to answer it.

→→↓←←↑
  1. 1

    Frame the decision

    The questionWho acts on this output, and what does a wrong answer cost?

    What I buildA success metric and a guardrail metric, written before any code.

  2. 2

    Get the data right

    The questionWhat do we actually know, and when did we know it?

    What I buildPoint-in-time tables, data contracts and quality checks with control limits.

  3. 3

    Design the agents

    The questionWhich steps need judgement, and which need rules?

    What I buildOne job per agent. Code executes. A checker can veto.

  4. 4

    Ground and evaluate

    The questionHow will we know it works before users find out?

    What I buildA labelled eval set and a simple baseline. It ships only if it beats the baseline.

  5. 5

    Guard in code

    The questionWhat must never happen, whatever the model says?

    What I buildPermission policy, approval gates and an audit log.

  6. 6

    Run and measure

    The questionIs it still worth what it costs?

    What I buildDrift, veto, override and cost-per-decision tracking that feeds stage 1.

Stage 6 feeds stage 1: production numbers shape the next decision.

Principles

  • A baseline before a model

    If a rule or a SQL query gets most of the way, the agent has to beat that, not zero.

  • Unverifiable beats confidently wrong

    A system that says “not enough evidence” keeps trust. One wrong verdict can lose it.

  • Small models, small decisions

    Shrink what the model has to decide. Let deterministic code do the rest.

  • Safety lives in code

    A prompt can be ignored or injected. A permission check cannot be talked out of.

  • Cost per decision is a product metric

    Tokens and latency belong on the same dashboard as accuracy.

  • If it isn’t logged, it didn’t happen

    Every input, retrieval, output and approval is traceable after the fact.

What I track in agent systems

Accuracy alone hides most failures. These six numbers show where a system is breaking.

Task successShare of eval tasks completed correctly, end to end.
GroundednessShare of claims tied to a cited, retrieved source.
Retrieval recall@kDid the right evidence make it into the top results?
Checker veto rateToo low means a rubber stamp; too high means weak proposers.
Human override rateHow often people disagree with the system, and why.
Cost and latency per runWhat each decision costs, and whether users will wait for it.

    A user forwards a message, an image or a link to the WhatsApp bot.

    Text, images and links are broken into separate claims that can be checked.

  3. Evidence foundretrieval

    Sources are gathered for each claim, and every fact keeps its source.

  4. Both sides argueagent

  5. Judge ruleschecker

    Any point without evidence is dropped. Thin evidence means “unverifiable”.

  6. Verdict cardoutput

Guardrail
