01 How I work

A delivery loop for AI systems

I run every build like a product with a metric attached. Each stage asks the product question first, then sets the engineering artifact that answers it. The loop closes when production numbers feed the next decision.

The question comes first, then what I build to answer it.

→→↓←←↑
  1. 01

    Frame the decision

    The questionWho acts on this output, and what does a wrong answer cost?

    What I buildA success metric and a guardrail metric, written before any code.

  2. 02

    Get the data right

    The questionWhat do we actually know, and when did we know it?

    What I buildPoint-in-time tables, data contracts and quality checks with control limits.

  3. 03

    Design the agents

    The questionWhich steps need judgement, and which need rules?

    What I buildOne job per agent. Code executes. A checker can veto.

  4. 04

    Ground and evaluate

    The questionHow will we know it works before users find out?

    What I buildA labelled eval set and a simple baseline. It ships only if it beats the baseline.

  5. 05

    Guard in code

    The questionWhat must never happen, whatever the model says?

    What I buildPermission policy, approval gates and an audit log.

  6. 06

    Run and measure

    The questionIs it still worth what it costs?

    What I buildDrift, veto, override and cost-per-decision tracking that feeds stage 01.

↺ Stage 06 feeds stage 01: production numbers shape the next decision.
02 Principles

What I hold to

A baseline before a model

If a rule or a SQL query gets most of the way, the agent has to beat that, not zero.

Unverifiable beats confidently wrong

A system that says "not enough evidence" keeps trust. One wrong verdict can lose it.

Small models, small decisions

Shrink what the model has to decide. Let deterministic code do the rest.

Safety lives in code

A prompt can be ignored or injected. A permission check cannot be talked out of.

Cost per decision is a product metric

Tokens and latency belong on the same dashboard as accuracy.

If it isn't logged, it didn't happen

Every input, retrieval, output and approval is traceable after the fact.

03 Metrics

What I track in agent systems

Accuracy alone hides most failures. These six numbers tell me where a system is breaking.

Task success

Share of eval tasks completed correctly, end to end.

Groundedness

Share of claims tied to a cited, retrieved source.

Retrieval recall@k

Did the right evidence make it into the top results?

Checker veto rate

Too low means a rubber stamp; too high means weak proposers.

Human override rate

How often people disagree with the system, and why.

Cost and latency per run

What each decision costs, and whether users will wait for it.
